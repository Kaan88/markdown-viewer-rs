# W0: first run on your Windows 11 PC

So far this has only run in a Windows 11 VM with no GPU, over RDP, at 100% scale. Your PC is the first real hardware, so expect some failures. Each one is useful.

## Which build to try

| Folder | What it needs | Try |
|---|---|---|
| `stage/self-contained` | Nothing installed. Copy the whole folder. | First |
| `stage/framework` | Windows App Runtime 2.6.4 or newer, x64. Install it from <https://learn.microsoft.com/windows/apps/windows-app-sdk/downloads>. This build has never been run. | Second |

Copy the folder to a local disk, not a network share. If Windows blocks it as downloaded, run `Get-ChildItem -Recurse | Unblock-File` in the folder.

**Smart App Control:** the exe is unsigned. If Smart App Control is on, it may block the exe, and `Unblock-File` won't help. Check Windows Security, App & browser control, Smart App Control. If it is on, say so and stop; don't turn it off for this, because it can't easily be turned back on.

All commands below are for PowerShell, run from the folder holding the exe.

## 1. Launch

Run `.\mdview-winui.exe --trace` and check the window:

- [ ] A window appears with two tabs, `showcase.md` and `linked.md`.
- [ ] A menu bar (File), a tree on the left and a Find box at the bottom appear just after the first frame.
- [ ] Mica is not expected yet. Say if it looks wrong anyway.

If startup fails, a message box should say why, and the process should exit when you dismiss it. If no window and no message appear:

1. Copy `mdview-winui.trace.log` from beside the exe straight away, because each launch replaces it. Its last line shows how far startup got.
2. Look in Task Manager, Details, for `mdview-winui.exe`. If it is there, end it, and tell me it was left running.
3. Check Event Viewer, Windows Logs, Application, for a crash entry.

## 2. Pixels

In Settings, System, Display, set each scale you can: **150%, 175%, 225%**. Settings only offers the scales your display supports, so 175% or 225% may be missing. Don't add a custom scale. Test what's offered, say which were missing, and include the highest one. Relaunch at each, and also try changing it while the app runs.

- [ ] The right panel is a sharp, even 1 px black and white checkerboard. Moire, stripes or grey areas mean scaling is wrong.
- [ ] Resizing the window keeps it sharp and has no black gaps.

A phone photo or a Win+Shift+S capture zoomed to 400% is the best check. Viewed at less than 100%, a good checkerboard looks flat grey.

## 3. Controls

- [ ] **Wheel:** scrolling over the checkerboard moves a blue band.
- [ ] **Lazy tree:** expanding `fixtures (lazy)` shows `showcase.md`, `linked.md` and `assets`.
- [ ] **ContextFlyout:** right-clicking the tree shows `Open in new tab`. Clicking it changes the window title.
- [ ] **TextBox:** the Find box takes typing.
- [ ] **Menu:** File, Close closes the window and the process exits. Check Task Manager.
- [ ] **Theme:** switching Windows between dark and light restyles the controls. The checkerboard stays the same.

## 4. Numbers

```powershell
powershell -ExecutionPolicy Bypass -File .\measure.ps1 -Runs 10
```

Windows will flash up ten times. Do this for both folders and send the output, plus your CPU and disk type. Numbers are reported, not a gate. Each run's trace is kept as `trace-run1.log` and so on.

## What to send back

- `measure.ps1` output for both builds
- The checklist above, with anything that failed, and which scales were available
- `mdview-winui.trace.log` or the `trace-run*.log` files for any failure

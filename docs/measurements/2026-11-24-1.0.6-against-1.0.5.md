# main (the next release, 1.0.6 if it keeps that number) against 1.0.5, before the release

Measured 2026-11-24 on the Windows PC, interleaved runs of two release builds, each in its own
worktree: A is the tag `v1.0.5` (`0a9bc7c`), B is `main` at `340fddf` (audit 4's fixes, shared
pinned at `ef88814`). `fixtures/showcase.md`, the default 1280x800 window, `--no-session`, and
for every start a fresh scratch folder named by both `MDVIEW_SETTINGS` and `MDEDIT_SETTINGS`
(so B's helper thread that looks for the notes library runs, and finds none).

Per run and build, two starts, by a script kept outside the repository:

1. With `MDVIEW_STARTUP_TRACE`: the first frame and the window shown, from the trace. mdview has
   no `--behind`, so the script moves the window off screen (`SetWindowPos`, no size change, no
   activation) as soon as it exists; it still appears in front for a moment. Private memory and
   working set 3 s after start, CPU time from 3 s to 6 s, then the window is closed (`WM_CLOSE`).
2. `--scroll-steps 300`: the frame summary it prints (own work: layout, paint, compose and copy;
   not the OS present). This window stays where it opens, for the second or so it runs.

**Verdict.** No change. The first frame moved by about 9 ms either way between the two rounds,
inside the ranges both times; memory, idle CPU and the scroll frame are the same.

- **The first frame.** Round 1's +9 ms was spread over every stage, from the event loop on
  (14.1 / 16.2 ms) to the first frame drawn (75.9 / 84.2), before any code that changed runs;
  round 2 turned it to −7 ms. Read as noise. Both medians are near mdview's 100 ms budget, as in
  section 9 of `docs/HANDOFF.md` (79 to 107 ms on the showcase).
- **Idle CPU.** 0 in most runs; otherwise one to four ticks of Windows' clock (15.6 ms each) in
  3 s, in both builds (round 2: A 8 runs of 0, two of 15.6, one of 46.9; B 7 of 0, two of 15.6,
  one of 31.2, one of 62.5). Frames drawn in that time were not counted (that needs
  `MDVIEW_TRACE`, which was off). The engine process, if the showcase starts one, is not counted.
- **The scroll frame.** The median and p90 are the same; the max is one slow frame per run in
  both (about 27 to 41 ms, one of 129 ms in A), well over 4 ms but not new.
- **The launch path.** New in B: a helper thread, started once the window runs, that looks for
  mdedit's notes library (`notes::find_library`); it reads nothing of the library at launch and
  only when a settings file of mdedit's is named or the session is the real one. `App::new` no
  longer reads mdedit's settings itself (audit 4). No new crate; `Cargo.lock` moves the shared
  pin to `ef88814` and two patch versions (`ratex-types` 0.1.15 to 0.1.16, `regex-syntax`
  0.8.11 to 0.8.12).
- **The exe.** `mdview.exe` 9,388,544 bytes in A, 9,547,264 in B (+158,720, 1.7 %: the notes
  face, the zoom view of a diagram). `mdview-engine.exe` 26,112,512 and 26,115,072.
- **Not measured.** The tests were not run here for this measurement (they were run for audit 4's
  fixes; see `docs/HANDOFF.md`); a 1 MiB document; a launch with a session (it would use the
  owner's settings); idle beyond 6 s; Linux and macOS.

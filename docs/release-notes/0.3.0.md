Command palette, settings, edit in mdedit with live preview, page fonts, and a Linux version.

mdview 0.3.0 is the first release for Linux and the first since 0.2.2. Version 0.2.3 was never
published, so this release also holds its changes.

## What is new

- A command palette (fuzzy search over every command, with "Go to line").
- A Settings dialog, including page and code fonts (any installed family), the preference
  toggles and page widths that were in the main menu, the update controls, and "Make mdview the
  default" on Linux.
- "Edit in mdedit" (Ctrl+E) opens the file in the editor at the line at the top of the page. With
  mdedit's "Preview in mdview" the page shows the editor's unsaved text as you type (live preview),
  and follows the caret. If the editor closes, the page returns to the saved file.
- Emoji in colour, including emoji with the variation selector, and a bare check mark or heart now
  draws as a glyph on Windows (it drew as an empty box there).
- The remote-image bar follows the "always load" setting and what the page shows, and cached
  remote images are no longer drawn in a tab that may not load them. Menus taller than the window scroll and
  stay below the title row; a submenu opens beside its parent and a wheel turn over an open menu
  no longer closes it.
- A window shadow (KDE's own on KDE, a drawn one on other Wayland desktops, none on X11).
- Checked menu items have their own check-mark column.
- The same viewer on Linux, with native file dialogs, the window's own icon in the panel, and an
  update check.

## Downloads

Windows

- `mdview-setup-0.3.0.exe`: the installer. Per user, registers the Markdown extensions under "Open with" and takes no `.md` default. Updates itself.
- `mdview.exe` and `mdview-engine.exe`: the bare executables; keep them in one folder. They update themselves (both files).
- `mdview-0.3.0-windows-x86_64.zip`: the two executables with LICENSE and README.md, as a portable folder. Updates itself if the folder is writable.

Linux (x86-64)

- `mdview-0.3.0-linux-x86_64.AppImage`: runs on any distribution; make it executable and run it. The engine is inside it. Updates itself.
- `mdview-0.3.0-linux-x86_64.tar.gz`: `install.sh [PREFIX]` (default `~/.local`) and `uninstall.sh`. Does not update itself.
- `mdview_0.3.0_amd64.deb`: Debian 11+, Ubuntu 20.04+ and derivatives. Does not update itself.
- `mdview-0.3.0-1.x86_64.rpm`: Fedora, openSUSE, RHEL and derivatives. Does not update itself.
- `PKGBUILD`: Arch. Put it in a folder and run `makepkg -si`; it installs the tar.gz as `mdview-bin`. Does not update itself.

`mdview-update.txt` is the update manifest the app reads; it is not for download.

The deb, rpm, tar.gz and Arch installs install a desktop file, so the taskbar icon and "Open with"
work without the AppImage's first-run registration. The AppImage writes its own desktop entry and
icon on first run and registers its file types without taking a default.

Linux needs glibc 2.31 or later (the builds are made in an Ubuntu 20.04 container), and the
system's fontconfig, freetype and X11/xcb libraries. libcurl and the Wayland libraries are loaded
at run time if present.

## Known limits

- The Windows files are not code-signed, so SmartScreen may warn.
- Windows was checked by automated tests and screenshots on a Windows runner (the full test suite
  and every screenshot state, built natively), not by hand. The installer wizard clicked through
  by a person, taskbar and Explorer icons, SmartScreen with unsigned files and interactive use on a
  Windows desktop have not been checked.
- Linux was run on KDE Plasma 6 (Wayland) and on sway. GNOME, other desktops, X11, fractional
  scales in a real window and monitors with different scales have not been tried.
- x86-64 only: no ARM builds. The deb and rpm are not signed.

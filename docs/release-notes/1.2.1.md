mdview 1.2.1: fixes for crashes and hangs in Markdown rendering, task checkboxes that tick the right box, and a safer hand-over between windows.

This release moves mdview onto the latest shared toolkit (`markdown-shared-rs` `48eedb8`). The
fixes below are in that shared code, which mdview builds in.

## Crashes and hangs

- **Front matter with non-ASCII text in a large file** (over 16 KiB) no longer closes the app.
- **Alerts written out of order** no longer close the app.
- **List numbers in Roman numerals above 3999** no longer hang the page.
- **Very deeply nested Markdown** is capped at 128 levels, and its text is kept.
- **Settings**: the arrow keys on an empty choice no longer close the app.
- **The update download** on Linux and macOS can no longer close the app.

## Fixes

- **Task checkboxes** tick the box you clicked, or do nothing when the file has changed
  underneath, instead of ticking another one. A box inside a comment, indented code, a formula
  block or front matter no longer shifts which box is written.
- **Long pages** scroll correctly past the point where very tall pages used to go wrong, and pages
  with many dropped blocks lay out faster.
- **Remote images** load through a queue.

## Opening a second window

When you open a file while mdview is already running, the new copy now proves to the running one
that it belongs to the same user before it hands the file over. A window still running from
before the update does not accept files from 1.2.1: close it once after updating. mdedit 1.6.1
makes the same change, so update both.

## Linux

The AppImage updates itself only when it is started as the AppImage, not when the program inside
it is run on its own. It keeps a small `.lck` file beside the AppImage while it updates.
